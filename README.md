# Nova


### A custom compiled programming language built from scratch in C++

**Nova** is a custom programming language and compiler designed around a game-inspired syntax. The project implements the core stages of a compiler — **lexical analysis, parsing, AST construction, LLVM IR generation, and execution** — without relying on parser generators.

Nova programs use a custom vocabulary such as `loot`, `skill`, `when`, `otherwise`, `grind`, `reward`, and `finish`, giving the language its own distinct programming model while retaining familiar programming concepts such as variables, functions, conditionals, loops, arrays, expressions, and function calls.

The compiler is implemented in **C++17** and uses **LLVM** for intermediate representation generation and JIT execution. Nova can also emit LLVM bitcode targeting **WebAssembly**, allowing programs to run through the project's browser-based playground.

---

## ✨ Features

### Language

Nova currently supports:

* Variables using `loot`
* Functions using `skill`
* Function calls using `call`
* Return statements using `reward`
* Conditional statements using `when` / `otherwise`
* While loops using `grind`
* Loop control using `break` and `continue`
* Arithmetic expressions
* Comparison operators
* Logical operators using `and` / `or`
* Assignment and compound assignment operators
* Unary expressions
* Grouped expressions
* Arrays
* Array indexing and assignment
* Strings
* Comments
  * Single-line comments using `#`
  * Multi-line comment support `/*`
* Built-in runtime functions
* Runtime array bounds checking

The lexer maintains the language's complete keyword and operator vocabulary through an X-Macro based token definition, providing a single source of truth for token declarations and their textual representations.

---

## 🔤 Lexical Analysis

The lexer is implemented from scratch in C++.

It converts Nova source code into a sequence of tokens while tracking:

* Token type
* Token value
* Source line
* Source column

The lexer handles:

* Numbers
* Strings
* Identifiers
* Nova keywords
* Arithmetic operators
* Comparison operators
* Logical operators
* Assignment operators
* Parentheses
* Brackets
* Comments
* Lexical errors

Nova's token vocabulary is defined through an X-Macro list, meaning a new token can be added to a central definition rather than manually synchronizing multiple token declarations and lookup structures.

---

## 🌳 Parser & AST

Nova uses a **recursive-descent parser** implemented entirely in C++.

The expression grammar is separated into precedence levels:

```text
assignment
    ↓
logic OR
    ↓
logic AND
    ↓
equality
    ↓
comparison
    ↓
term
    ↓
factor
    ↓
unary
    ↓
call
    ↓
primary
```

This allows expressions such as:

```nova
loot result = (10 + 5) * 2
```

to be parsed according to the correct operator precedence.

The AST contains separate nodes for expressions and statements, including:

* Literal expressions
* Variable expressions
* Binary expressions
* Unary expressions
* Grouping expressions
* Assignment expressions
* Logical expressions
* Function calls
* Array literals
* Array indexing
* Array assignment
* Variable declarations
* Expression statements
* Blocks
* Conditionals
* Loops
* Functions
* Returns
* `break`
* `continue`

The AST uses the **Visitor pattern**, allowing the code generator to operate on nodes without relying on chains of runtime type casts.

---

## ⚙️ LLVM Code Generation

Nova generates **LLVM Intermediate Representation (LLVM IR)** from its AST.

The `CodeGen` component implements both the expression and statement visitor interfaces:

```text
AST Node
   │
   ▼
accept(visitor)
   │
   ▼
CodeGen Visitor
   │
   ▼
LLVM IR
```

LLVM provides the lower-level infrastructure required for:

* IR construction
* Module management
* LLVM verification
* Native execution
* JIT compilation
* WebAssembly bitcode generation

Nova currently uses LLVM's execution engine infrastructure for native JIT execution.

---

## 🚀 Execution Modes

Nova supports two primary execution paths.

### Native JIT Execution

Running the compiler normally generates LLVM IR and executes the resulting module using the local LLVM execution engine.

```bash
mycompiler program.nv
```

### WebAssembly

Nova can also emit LLVM bitcode configured for the `wasm32-unknown-emscripten` target:

```bash
mycompiler program.nv --emit-bc output.bc
```

The compiler explicitly configures the WebAssembly target and writes the generated LLVM bitcode to disk.

This makes it possible to integrate Nova with the browser-based playground included in the repository.

Nova includes a native runtime layer that exposes functionality to programs generated by the compiler.

The runtime provides functionality such as:

* Window creation
* Frame rendering
* Screen clearing
* Rectangle drawing
* Colored rectangle drawing
* Text rendering
* Number rendering
* Keyboard input
* Random number generation
* FPS configuration
* Window closing

The graphical functionality is backed by **raylib**.

This allows Nova to move beyond simple console programs and experiment with graphics-oriented applications.

## 🔧 Building the Compiler

### Requirements

Install:

* C++17 compatible compiler
* CMake 3.10+
* LLVM
* ZLIB
* raylib

The project currently requires LLVM to be discoverable through CMake's package configuration.

### Build

```bash
git clone https://github.com/GaneshNair05/Nova-Custom_Compiled_Language.git

cd Nova-Custom_Compiled_Language

mkdir build
cd build

cmake ..
cmake --build .
```

This produces the compiler executable:

```text
mycompiler
```

---

## ▶️ Running a Nova Program

After building:

```bash
./mycompiler ../examples/snake.nv
```

The compiler expects a Nova source file as its first argument.

```text
Usage:
mycompiler <source-file> [--emit-bc <output.bc>]
```

The default execution path generates LLVM IR and executes the resulting program through the JIT engine.

## 🧪 Language Example

A simple Nova program looks like:

```nova
loot x = 10
loot y = 20

when (x < y)
    x = x + 5
otherwise
    x = x - 5
finish
```

A function can be declared using `skill`:

```nova
skill add(a, b)
    loot result = a + b
    reward result
finish
```

And called using:

```nova
call add(10, 20)
```

# Nova Playground

A browser-based editor and runner for [Nova](../), the compiled language
built in this repo. Write Nova, hit Run, see the tokens, the LLVM IR, and
the program's output — all from the browser.

```
playground/
  backend/     Express server: runs submitted source against the compiler
  frontend/    Static site: Monaco editor + output console
```

## Quickstart

```bash
cd playground/backend
npm install
npm start
```

Open **http://localhost:4000**. By default this runs in **demo mode** — no
compiler configured, so only the bundled examples (picked from the
dropdown, unmodified) produce output, with a banner saying so. That's
enough to look around without building anything first.

## Running your own code

Point the server at your actual compiled binary:

```bash
set NOVA_COMPILER_PATH=/absolute/path/to/mycompiler.exe   # or mycompiler on Linux/macOS
npm start
```

Once that's set, every `Run` click writes the editor's contents to a temp
`.nv` file and runs your real compiler against it — tokens, IR, and program
output all come from the actual pipeline, not canned data.

Other environment variables, all optional:

| Variable | Default | What it does |
|---|---|---|
| `PORT` | `4000` | Port the server listens on |
| `NOVA_TIMEOUT_MS` | `8000` | Kill a run that takes longer than this (catches infinite `grind` loops) |
| `NOVA_MAX_OUTPUT_BYTES` | `200000` | Stop capturing stdout/stderr past this many bytes (catches runaway print loops) |

## What this doesn't do (on purpose)

**Graphical programs are blocked.** Nova's raylib bindings
(`init_window`, `draw_rect`, `is_key_down`, …) open a real OS window,
which can't work against a headless server — there's no display for it to
draw to. The backend detects `init_window(` in submitted source and
returns a clear message instead of letting it hang. Snake and anything
else that opens a window is still meant to be run from the compiled binary
directly on your own machine. Streaming a virtual framebuffer into the
browser (Xvfb + screen capture) would make in-browser graphics possible,
but that's a meaningfully bigger project, deliberately not attempted here.

**Arrays and strings can't cross function boundaries yet.** This mirrors a
real limitation in the compiler itself, not something the playground adds
— `skill` parameters and return values are still numbers-only. Every
bundled example works within that limit (arrays/strings live at the top
level; skills that touch them read/write the globals directly).

## How output is parsed

`main.cpp` already prints three sections in a fixed order — the token
dump, then `--- Generating LLVM IR ---`, then `--- Executing Program ---`.
The backend splits stdout on those exact banner strings
(`backend/lib/runNova.js`, `parseSections`) rather than trying to
reconstruct structure another way. If you ever change what `main.cpp`
prints before running the program, update those two marker strings to
match, or the Tokens/IR tabs will come back empty and everything will show
up under Output instead.

## Demo mode

When `NOVA_COMPILER_PATH` isn't set, requests are matched (exact source
match, ignoring surrounding whitespace) against `backend/data/examples.json`
and served pre-recorded output from `backend/lib/mockExamples.js` — traced
by hand against the compiler's actual semantics (the tagged
`[tag][length][elements...]` heap layout, `%f`/`%g` print formatting, the
bounds-check error path), not run through a second interpreter. Anything
that isn't an exact match to a bundled example gets an explanatory message
rather than a guess. If you add or edit an example in `examples.json`, add
a matching entry to `mockExamples.js` too, or it'll fall out of demo mode.
